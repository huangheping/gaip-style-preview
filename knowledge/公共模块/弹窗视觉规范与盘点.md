# 弹窗视觉规范与盘点

> [!important] 处理边界
> 本页以视觉分类、问题清单和规范草案为主。后续必须按“基础层 → 类型层 → 个性层”逐层落地，不能用一组宽泛选择器强制覆盖全部弹窗。2026-09-03 已先完成第 10 项的单弹窗滚动条贴边修正，未提前套用全局视觉规则。

## 盘点口径

- 事实源：`shared/scripts/modal-registry.js`、`全局组件/弹窗源登记.js`、`全局组件/弹窗自动索引.generated.js`。
- 当前基线：35 个 `ready` 且非 `drawer` 的真实组件弹窗；抽屉、AI Agent 主面板与其他 `excluded` 项不进入本轮。“编辑对话名称”按全局复用操作弹窗纳入预览。
- 预览原则：继续调用真实打开入口和真实样式，不在预览页复制第二套弹窗。
- 关联架构：[[../决策/ADR-004-弹窗源自登记与自动索引|弹窗源自登记与自动索引]]。

## 为什么现在看起来乱

当前弹窗不是同一个视觉系统下的不同实例，而是多套历史实现同时存在。源码中已出现以下明显分叉：

| 项目 | 当前差异 | 直接后果 |
|---|---|---|
| 标题 | 16 / 18 / 20 / 24px 并存 | 同层级弹窗视觉权重不一致 |
| 表单控件 | 36 / 40 / 44 / 48px 并存 | 同一页面不同弹窗密度跳变 |
| 内边距 | 16 / 20 / 24 / 28px 等多套组合 | 标题、正文、底部按钮无法对齐 |
| 圆角 | 2 / 4 / 5 / 6 / 8 / 12 / 20px 并存 | 控件和容器像来自不同产品 |
| 文字颜色 | `#111827`、`#253b39`、`#2f3640`、`#374151` 等并存 | 主次层级不稳定 |
| 底部操作区 | 有固定 footer、正文内按钮、超大留白等多种结构 | 扫读和操作预期不一致 |
| 滚动 | 整体滚动、正文滚动、表格内滚动并存 | 长内容下标题和操作按钮容易丢失 |

> [!note] 判断
> 乱的核心不是“每个弹窗都需要完全一样”，而是缺少共同基础层和明确的个性化边界。

## 标准化分层

| 层级 | 内容 | 处理原则 |
|---|---|---|
| L1 全局令牌 | 字体、字号阶梯、文字色、品牌色、边框色、圆角、阴影、间距刻度 | 必须统一 |
| L2 弹窗外壳 | 遮罩、容器、标题区、关闭按钮、正文区、底部操作区、滚动行为 | 原则统一，尺寸按类型变化 |
| L3 基础控件 | 输入框、选择器、日期、搜索、按钮、表格、空状态、错误提示 | 必须统一状态和尺寸规则 |
| L4 类型模板 | 信息展示、表单操作、操作确认 | 同类统一布局，尺寸、滚动、风险等差异用属性表达 |
| L5 业务内容 | 字段组合、营销图片、步骤、表格列、领域状态、特殊说明 | 保留个性化 |

## 35 个弹窗的三类目录

预览页只使用三个一级分类，避免把“表格、滚动、尺寸、危险等级”也变成目录。这些差异属于后续的组件属性或变体。

| 一级分类 | 登记值 | 数量 | 范围 | 典型弹窗 |
|---|---|---:|---|---|
| 信息展示 | `information` | 13 | 详情、预览、记录、系统提示 | 03 操作日志、06 方案附件预览、09 资讯文章详情、21 线索详情、29 产品详情 |
| 表单操作 | `form` | 16 | 新建、编辑、选择、配置、分配、导入 | 08 保司关键词设置、10 配置中心成员编辑、15 批量导入成员、19 分配线索、22 新增线索 |
| 操作确认 | `confirmation` | 6 | 执行操作前的二次确认 | 05 方案解除关联确认、12 删除部门确认、17 调整管理员节点确认、26 删除客户确认 |

- 删除、解绑等不再单独建立一级分类，而是在“操作确认”下使用 `danger` 变体。
- 表格、详情、状态提示和流程是内容形态，不再占用一级分类。
- 预览页保留 01–35 原清单编号，即使按用途分组也能继续精确指向某一项。
- 新增可预览弹窗时，真实源登记必须提供 `category`；预览页只读登记数据分组，不维护按 ID 写死的分类名单。

## 视觉基线（操作确认已应用，其他类型仍为草案）

### 字体与颜色

| 令牌 | 建议值 | 用途 |
|---|---|---|
| 标题 | 20px / 28px，500，`#2F3640` | 普通弹窗标题 |
| 正文 | 14px / 22px，400，`#2F3640` | 内容、表单值、按钮 |
| 标签 | 14px / 22px，500 或 400 | 表单标签，是否加粗按信息层级 |
| 辅助文字 | 12px / 18px，`rgba(47,54,64,.62)` | 描述、时间、提示 |
| 占位文字 | `rgba(47,54,64,.38)` | 输入和选择器 placeholder |
| 品牌色 | `#025B52` | 主按钮、选中、链接、焦点 |
| 危险色 | `#CF1322` | 删除与不可逆操作 |
| 边框色 | `rgba(47,54,64,.14)` | 容器与控件边框 |
| 遮罩 | `rgba(0,0,0,.45)` | 全局弹窗、抽屉与嵌套确认遮罩；已由共享基础组件落地 |

### 尺寸与间距

| 项目 | 建议规则 |
|---|---|
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32px；不再随意新增 18、22、28 等孤立值 |
| 弹窗圆角 | 8px；营销或系统提示若需更强品牌感，可登记为个性例外 |
| 控件圆角 | 4px；标签、状态胶囊另设规则 |
| 标准控件高度 | 40px；仅大型选择/上传流程显式使用 48px |
| 标准按钮高度 | 40px；确认类与表单类保持一致 |
| 标题区 | 左右 24px，上下 20px；关闭按钮与标题视觉中心对齐 |
| 正文区 | 24px；紧凑确认类可使用 20px 类型模板 |
| 底部区 | 左右 24px、上下 16px；操作按钮右对齐，按钮间距 12px |
| 滚动 | 标题区和 footer 固定，只有 body 滚动；表格类允许表格内部滚动 |

### 建议宽度档位

| 类型 | 建议宽度 |
|---|---|
| 确认 / 系统提示 | 420–520px |
| 单字段 / 轻量表单 | 520–640px |
| 标准表单 | 720–900px |
| 详情 / 流程 | 900–1100px |
| 表格 / 日志 | 1100–1360px，并受视口最大宽度约束 |

## 不应全局统一的内容

- 不把所有弹窗固定为同一宽高。
- 不统一业务字段数量、分组顺序、表格列或富文本结构。
- 不删除海报、文件预览、批量导入、权限选择等专属交互。
- 不强制系统提示、危险确认和长表单使用同一信息密度。
- 不用 `.ant-modal *`、`dialog *` 等宽泛选择器覆盖真实业务组件。
- 不在 `全局组件/弹窗预览.html` 维护一套“看起来统一”的复制样式。

## 建议实施顺序

1. **基础令牌**：建立弹窗专用 CSS 变量，但暂不改变业务结构。
2. **外壳统一**：标题区、关闭按钮、正文、footer、遮罩和滚动行为。
3. **确认与系统提示**：先处理结构最简单、风险最低的 7 个弹窗。
4. **表单控件**：统一输入、选择、日期、搜索、校验、按钮和间距。
5. **表格弹窗**：统一筛选、表头、行密度、分页和滚动。
6. **详情与流程**：只套基础层，逐项登记个性例外。
7. **回归**：刷新真实源预览，逐个核对 35 个弹窗，不在预览页补丁修正。

> [!warning] 下一阶段的实现边界
> 建议先选“操作确认 6 个 + 信息展示中的系统提示 3 个”作为第一批。它们能验证标题、正文、按钮、圆角、遮罩和 footer 六项基础规则，同时不会立即碰复杂表单和表格。

## 验收清单

- [ ] 35 个真实弹窗均能从预览打开，且没有复制 DOM/CSS。
- [ ] 同类标题、正文、控件、按钮和间距使用同一规范。
- [ ] 键盘焦点、Esc、遮罩关闭和焦点恢复未被视觉修改破坏。
- [ ] 小视口下宽度不溢出，长内容只滚动 body。
- [ ] 个性化项有明确根类或 `data-*` 变体，不依赖全局覆盖顺序。
- [ ] 源弹窗变化后刷新预览即可同步。

## 已落地的局部修正

- 全局定位基础组件：`shared/styles/global-modal-position.css` 与 `shared/scripts/global-modal-position.js` 是普通弹窗视口位置的唯一共享来源。Ant Modal、原生 dialog 和已登记自定义弹窗统一水平/垂直居中，桌面/窄屏安全边距为 24/12px；动态创建节点由 MutationObserver 自动接入。抽屉和 GAIP Agent 主面板排除，嵌套确认只在主弹窗内部居中。弹窗预览舞台统一为 820px 高，消除各登记项 iframe 高度不同带来的视觉假偏移。
- 全局遮罩基础组件：`shared/styles/global-modal-mask.css` 是遮罩颜色、透明度、动效时长与减少动态偏好的唯一视觉来源，统一覆盖原生 `dialog::backdrop`、Ant Modal / Drawer 以及活动、资讯、方案、财富、AI 提示、海报分享和配置中心嵌套确认层。业务 CSS 只保留尺寸、内容结构与层级，不再持有遮罩视觉值；正式根入口与真实弹窗预览均加载同一共享文件。

- 10 `config-member` 配置中心成员编辑：弹窗主 body 铺满可用宽度并独立滚动，滚动条贴弹窗右缘；标题和 footer 固定，字段内容仍保留 `24px` 内边距。改动仅由真实源 `.formModal____MTrk` 持有，预览页没有复制样式。
- 操作确认 6 项已全部接入同一共享组件：05 `proposal-unlink` 使用普通品牌色确认；12 `config-delete`、25 `customer-meeting-delete`、26 `customer-delete`、35 `config-announcement-delete` 使用危险红主按钮；17 `config-adjust-member-node-confirm` 使用危险态与 520px 复杂确认规格。各业务原有确认、取消、关闭与数据逻辑保持不变。
- 12 `config-delete` 同时覆盖禁止态：可删除时只显示确认问句；仍含子部门或成员时显示普通说明并禁用主按钮，不使用警示图标或红色说明文字。

### 共享弹窗组件 v1.1.3

- 逻辑入口：`shared/scripts/global-modal.js`，公开 `adopt()` 与 `setConfirmState()`；支持普通 Ant Modal、自建 Ant 兼容 DOM 和 Ant `Modal.confirm` 系统确认框。系统确认框会在共享层归一为唯一的 title/body/footer，自动去除旧图标和重复文案，并补齐标准关闭控件；所有接入项都会移除弹窗关键节点上的旧业务哈希样式类，并由共享层重建同一个关闭图标。
- 样式入口：`shared/styles/global-modal.css`，所有规则只使用 `.gaip-modal*` 组件命名，不包含部门名称或业务文案。
- 当前范围：操作确认分类的 6 个真实弹窗已全部接入；CSS 缓存版本为 `20260904-4`，JS 缓存版本为 `20260904-5`。

> [!important] 操作确认视觉规范已确认
> 用户已于 2026-09-04 接受统一方案。6 个现有弹窗已按 12 → 05 → 25 → 26 → 35 → 17 的顺序逐个迁移、回归与截图验收，没有使用一次性 `.ant-modal` 全局覆盖。

确认弹窗当前参数：默认宽度 480px，复杂信息可使用 520px；圆角和内容内边距分别为 8px、24px；用户手动调整后的标题为 18/28px、700，正文为 14/24px，补充说明为 14/22px；关闭点击区 32px、图标 16px；正文与 footer 间距 32px；按钮高度 40px、圆角 4px、间距 12px，取消在左、确认在右。默认无警示图标且不滚动；危险态只通过红色主按钮表达，禁止态使用普通说明和禁用主按钮。

### 操作确认的未来项目契约

- 现有 6 个操作确认弹窗和以后新增的操作确认弹窗，均必须调用同一共享组件和已确认的标准样式。
- 业务页面只提供标题、确认文案、补充说明、按钮文案、危险等级和禁止原因；不得复制外壳 DOM，或另写一套按钮、标题和关闭控件样式。
- 强制登记保持 `category: "confirmation"` 与 `type: "confirm"`；危险操作通过组件变体（如 `tone: "danger"`）表达，不另拆弹窗类别。
- 定版时必须同时锁定设计令牌、组件 API、无障碍行为、回归测试和预览验收清单，防止后续任务再次产生局部特例。
