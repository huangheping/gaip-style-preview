# 项目维护规则

## 范围与来源

- 确认目标项目根及已有改动；仓库已初始化时检查 Git 状态和目标 diff，保留其他任务工作。用户指定入口时核对地址所属项目。
- 根据任务查 `PROJECT_STATE.md`、`knowledge/INDEX.md` 和相关规范；已读且未变化的不重复加载。仅解释/审查不自动授权实现；修改/修复请求完成范围内本地工作和相称验证，不重复请求已有授权。
- 抽离任务的来源全部只读，复制、改造、缓存、测试与记录只写来源外的明确目标。本项目成果、临时截图/导出和验证输出归本项目；临时产物放 `outputs/`，不引用其他项目路径。
- GitHub 操作按 `docs/github-sync-rules.md` 和实际用户授权执行，不自动提交、推送或部署；项目规则不替代宿主权限。

## 标准化

- 频道在各自 `channels/` 维护 HTML、CSS、JS 和私有资产；共享 UI 归 `components/`，知识双链/索引归 `knowledge/`。业务和预览调用同一组件源。
- HTML 禁止内联 CSS、执行脚本和事件，允许 link 加载独立 CSS。JS 禁止固定样式、拼接 style、注入样式表或 React style 对象；状态用 class/data/hidden，必要动态几何值先逐项评审，不能用变量隐藏固定样式。静态结构归 HTML，数据/事件归 JS。
- AOCI 须为本项目独立安装、初始化和建立真实索引，不复制来源的认知、baseline 或收据。使用实时工具合同；空骨架、待作者编写和已对齐是不同状态，待编写不等于工具阻塞。GAIP 专属技能不适用于本项目；确有重复工作时再创建窄范围本地技能。

## 验证与交付

- 首次需要检查时安装开发依赖，已有可用依赖直接复用；运行 `npm test` 验证结构和 JS 样式归属。业务变化另选相关验证，不重复无关套件。
- 必需项分别记录通过、未通过或未验证；静态、DOM 和真实浏览器结果分开，不把骨架、工具成功或旧截图当业务完成。真实权限拒绝不得绕过。
- 修改后更新本任务知识/状态摘要；交付核对报告与证据可读，说明实际增量、验证范围及剩余项。本地完成不等于发布。
