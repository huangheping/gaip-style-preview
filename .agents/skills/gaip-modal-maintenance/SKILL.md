# GAIP 弹窗维护

让业务与预览使用同一真实弹窗，保持开/关、重开、底层点击和焦点生命周期。遵守目标仓库 AGENTS 的范围、抽离例外及交付规则；诊断请求不自动授权实现。

以下链接相对本技能目录，命令在已确认的 Git 根运行。确认该根含 `shared/scripts/modal-registry.js`。

## 找到真实源

定位实际 `open/show/create`、显隐状态、业务回调和所属 CSS；区分 Ant Modal、原生 dialog、自定义宿主、抽屉及 AI 主面板。共享层问题查 [全局框架](../../../knowledge/公共模块/全局框架与样式.md)；新增/登记查 [ADR-004](../../../knowledge/决策/ADR-004-弹窗源自登记与自动索引.md) 与 [维护流程的登记字段](../../../docs/maintenance-workflow.md)。无需为局部修复读全部弹窗历史。

## 修改与验证

- 操作确认复用共享组件；遮罩/定位修改归共享源，业务内容归所属源，不在预览复制外壳。调用参数遵循现有接口，不凭组件名称重写业务流程。
- 验证初始关闭 → 打开 → 关闭 → 底层点击 → 再开；检查 `display:none`、`hidden`、`inert`、遮罩命中、Escape 和焦点恢复。布局规则不能强行显示已关闭宿主。
- 按证据排查重复事件、观察器循环/泄漏及 React 节点破坏；保留原节点与业务回调，不把所有点击问题归于历史遮罩故障。
- 登记变化运行 `node scripts/generate-modal-catalog.cjs`；生成清单不手改。真实业务弹窗/共享层/登记任务运行生成器 `--check` 与 `node scripts/test-popup-preview.cjs`，业务改变再按维护矩阵追加对应测试；局部样式任务按矩阵处理，不自动扩成全套回归。
- 层级、布局和点击验收使用工具允许的真实浏览器；模拟结果不能证明命中或原生顶层。当前工具拒绝时记录具体缺口，不换通道绕过。

输出成因、真实调用源与消费者、生命周期检查证据及具体未验证项；保持本地模拟与真实服务的区别。记录和 AOCI 收尾复用根规则。
