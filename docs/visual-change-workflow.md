# 视觉样式：边修改边记录

生效日期：2026-09-07。适用于本项目日常设计修改。用户已确定后续通过 Codex 修改，以每轮任务同步记录代替交付时重新全站寻找差异。

## 官方依据与本项目约定

已读取 [OpenAI AGENTS.md 指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 与 [OpenAI 最佳实践](https://learn.chatgpt.com/guides/best-practices)。官方建议将可复用工作方式和完成条件写入项目指令，根文件保持简短，细节引用专项文档，并执行相关验证。本文件的视觉属性范围、记录格式和标注方式是本项目约定，不是官方提供的设计交接标准或内置自动记录功能。

从实际 Git 根 `样式优化html` 开始任务更容易加载本项目指令。从父目录启动时，应先显式读取本目录 AGENTS.md；目录发现不会自动遍历所有子项目。已运行任务也不保证即时重读新增规则。

## 记录什么

只记录可交付的视觉参数：图标资源及尺寸/颜色；字体、字号、字重、文字颜色、行高；宽高及 min/max 约束；padding、视觉 gap/margin；圆角、边框、背景、阴影。margin 仅记录元素之间的视觉间距，不将整个区域的位置迁移包装成间距改动。

搜索框记录自身样式，不记录上移/换区域或搜索逻辑。位置、页面结构、导航、交互、接口、权限和业务数据进入对应产品文档/维护记录，不生成视觉标注。发现文档未覆盖的逻辑变化时说明缺口，不丢失信息；相关业务测试仍按维护流程执行。

未来交付以新版可运行页面为标注载体；标记跟随元素，详情包含旧值、目标值、必要局部截图和代码位置。同一组件多处实例只标一个代表，列清适用范围。此规则文件与记录模板本身不提供标注界面。

## 每轮执行顺序

1. 读取本次页面/共享组件记录与拥有该样式的源码，核对已有工作区修改。首次修改某元素前保存可获得的旧值和来源；不可在覆盖后仅凭记忆补写旧值。
2. 建立/复用稳定记录 ID，识别组件、页面状态、代表元素与适用范围。定位优先已有语义属性和稳定选择器；不靠截图坐标或行号单独识别元素。不为了记账擅自大改 DOM。
3. 按用户要求修改。一个任务内连续试调可集中在一轮稳定结果后更新，长任务在完成一个组件后及时落盘；不要每次工具调用都写日志或截屏。
4. 收尾更新同一记录的最终参数和相关源文件依据，核对本轮实际 diff，补漏掉的直接或共享视觉变化。最终值来自当前代码/实际渲染，不能只抄原计划。
5. 对变动属性和受影响状态进行相称验证；更新验证级别和未完成项。完成回复简述已记录的页面/组件与核验边界。

无视觉变化的文档、逻辑或重构任务不建空记录；纯代码重排不生成标注。本轮规则维护也不回填整个项目历史。

## 三种值必须分开

- **交付基准 baseline**：前端要对照的指定版本。可来自已采集的测试环境、双方指定的提交/构建版本或用户明确指定的本地快照。记录来源、时间、版本（未知则留空）及取样状态。普通本地 commit、GitHub 预览发布不自动成为新的前端交付基准。
- **首次本地值 initialLocal**：第一次记录之前，本地元素的值/源规则。它可能已与线上不同，只用于追溯本轮起点，不能冒充线上旧值。
- **当前目标 target**：这一交付周期最后确认到的设计效果。反复调整只覆盖此值，保留基准。

例如指定线上基准字号14，首次本地已是13，继续修改到12：标注为14→12，同时保留首次本地13。线上基准未知时 `before` 为 null，标明“基准待补”；可以继续完成本地修改和记录，不阻塞任务、不猜测旧值，也不能把首次本地值直接当线上值。

已保存且适用的基准按需复用，不每轮重开线上。没有基准时可以延后对目标元素补采；新页面按范围逐步建立基准，不为改一个图标扫描全站。

## 文件与最小记录格式

视觉参数唯一手工台账为 `design-changes/<page-or-component>.json`。从 [空模板](../design-changes/_template.json) 建立，在 `records` 中写记录。下面仅说明字段形状；null 表示未采集，不能作为已完成的真实记录复制交付。

```json
{
  "id": "organization.member-tags.default",
  "element": "成员表格标签",
  "locator": { "selector": null, "representative": null },
  "state": { "channel": null, "variant": "default", "viewport": null },
  "appliesTo": [],
  "baseline": { "id": null, "kind": "unknown", "ref": null, "capturedAt": null, "evidence": [] },
  "properties": {
    "font-size": { "before": null, "initialLocal": null, "target": null, "status": "active", "basis": "unknown" }
  },
  "sources": [],
  "verification": { "level": "needs-recheck", "checkedAt": null, "gaps": [] },
  "status": "active",
  "updatedAt": null
}
```

- `baseline.kind`：`online` / `agreed-commit` / `agreed-local` / `unknown`。首次确定后冻结该交付周期基准。一个状态用一个基准记录。
- `locator` 填实际核对的选择器及代表元素说明，避免只靠不稳定的生成类名；多匹配本身可合理，必须限定容器/范围。
- `state` 填与样式相关的渠道/组件变体、default/hover/focus/disabled等状态及断点；只采涉及的状态，不强制遍历全部状态。状态不同，不把值合并到一条属性上。
- `appliesTo` 写实际受影响页面/实例；公共组件按消费者列范围，未知覆盖写入 gaps，不宣称全站已经核验。
- `properties` 只保留变化或待确认的属性，值带单位。尺寸响应式规则如 `max-width:333px` 原样保留；截图测得的宽度写入证据，不把它直接改成固定宽度要求。
- 属性 `basis`：`computed` / `source` / `mixed` / `unknown`，说明证据性质；必要时另附 `beforeBasis`、`targetBasis`，避免把源码值说成浏览器实测。新增图标/组件的旧值可为 null，需补 `reason: "new"`，区别于基准未知。
- 图标属性可用 `icon.asset`，同时记录新旧资源相对路径/可获得的哈希、引用位置和宽高；不能只写“换了一个图标”。
- `sources` 填拥有规则的文件、选择器或函数、可选行号及本轮文件哈希。只读写相关文件，不为每次修改遍历全仓计算哈希。截图放 evidence 相对路径，不将图片 base64 或整页代码复制进台账。
- `verification.level`：`source-only` / `browser-checked` / `needs-recheck`；`browser-checked` 只用于实际核验的元素和状态，不表示整个业务页面都通过。

## 合并、恢复与交付周期

同一基准 + 组件 + 状态 + 属性只有一个当前目标：14→13→12 最终记14→12；同类多个实例不重复建记录。修改已有记录前重读相关条目，保留其他任务内容；共享组件同一属性发生冲突时核对实际源规则和用户最新要求，不用陈旧记录覆盖。

属性目标恢复为已知基准时，将该属性标为 `reverted`；只隐藏该属性的标注，其他仍不同的属性继续保留。全部恢复时整条记录为 `reverted`。基准未知时不能仅凭恢复首次本地值就断言线上无差异。

样式或引用再次修改，原验证置为 `needs-recheck`，完成相关核验后再更新。元素定位失效只重定位受影响项，不默默丢弃记录。历史记录在前端接收/实现状态明确、需开启新周期时归档到 `archive/<baseline-id>/`；建立新基准要有明确依据，不能因本地代码提交或设计预览发布自动清零待交付项。

## 何时需要扩大核验

日常只核对当前元素、相关属性、当前 diff 与记录。公共 CSS/字体变化检查实际消费者的代表页面；状态或媒体查询变化检查对应状态/断点。下列情况再扩大：指定线上基准版本改变、共享组件大改、选择器大量失效、发现台账漏项或发生视觉异常。已有验证仍适用时不重复跑无关套件。

交付前按记录核对当前目标、元素定位、局部效果和相关消费者。基准或浏览器不可用时完成源码检查并列缺口，遵守工具访问限制，不能绕过拒绝。记录减少重复调查，不能代替最终视觉核验；不承诺固定 token 节省比例。

## 与既有流程和抽离规则衔接

当前未发布变更、PROJECT_STATE 和模块笔记保留摘要/关系/记录链接，不再次手抄视觉数值。默认只加载当前文件及相关条目，不遍历整个 design-changes、全部截图或历史记录。

日常源项目设计修改在本项目记录；抽离任务仍以来源只读为边界，只将已有记录及必要证据复制到独立目标。抽离时发现缺口可在目标包记“待核验”，不得为完善台账回写来源。抽离快照的后续调整在目标包独立维护。

## 规则检查场景

| 场景 | 应有结果 |
| --- | --- |
| 标签字号连续试调三次 | 同一基准只留最终目标；没有三条重复交付项 |
| 仅移动搜索框 | 无位置标注；若圆角同时变化，只记录圆角 |
| 只换图标 | 记录资源依据和尺寸，不扫描其他频道 |
| 一项恢复原值，另一项仍不同 | 只取消已恢复属性的标注 |
| 线上未知、本地已改过 | 基准待补，分别保留首次本地值与目标 |
| 共享标签 CSS 调整 | 一份共享记录、明确消费者并做相关核验 |
| 纯文档或逻辑任务 | 不生成视觉记录，遵守相应维护检查 |
| 独立抽离 | 读取并复制现有记录，来源不写入 |

这些是规则推演与验收要求，不代表已经运行过自动监听、跨任务成功率评测或标注系统。
