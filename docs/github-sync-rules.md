# 本地 GitHub 同步规则

这是项目内 GitHub 同步流程的统一入口，整理自已有 AGENTS、维护流程、未发布清单和发布记录。整理规则不会执行提交、推送或部署，也不要求新建 GitHub Actions。上级入口：[[knowledge/INDEX|项目知识总索引]]。

## 2. 用户用语与执行边界

- “整理同步规则”“标准化本地 GitHub 规则”：维护本地文档和必要的入口，不执行 commit、push 或部署。
- “本地提交，不推送”：验证后执行本地 commit，到此结束；不执行 fetch、pull、push、远端同步或部署。无需为仅本地 commit 请求远端状态。
- “同步 GitHub”：在本次任务及仍有效授权范围内，核对要同步的变更后执行对应 Git 操作；不自动包含整个脏工作区。已明确的授权不重复询问。
- “发布预览”：除同步结果外，还需核验已有预览站的实际构建与页面结果；不能用本地提交代替线上证据。
- 普通代码修改、规则整理不自动扩大为全局设置、远程自动化或另一项目操作。
- 若同步现有分支会触发现有 Pages 部署，应在执行前识别该既有行为；不因本规则新增部署方式。

## 3. 实际同步时的顺序

1. **确认仓库与现状。** 在实际 Git 根检查当前分支、目标远端、已暂存/未暂存差异和未跟踪文件。远端状态必须新鲜核验；本地缓存不能直接证明 GitHub 当前状态。
2. **划定提交范围。** 对照当前任务和未发布清单列出文件/必要片段。保留其他任务、用户手工修改和明确不发布的候选，不用整目录全量暂存代替范围审阅。
3. **核验依赖。** 样式、脚本、素材、注册表、入口缓存版本、组件预览和必要知识记录形成完整交付；排除素材不得成为正式代码的必需依赖。
4. **完成相称验证。** 按维护流程选择检查并记录范围。若需发布快照，写到本项目输出目录；抽离任务写到指定独立目标，不向来源目录写文件。测试快照应只包含拟交付内容，避免本地排除资源掩盖缺失。
5. **审阅暂存差异。** 核对文件清单、内容和排除项，再提交本次范围。已有其他暂存改动需保留、隔离或明确归属，不能顺带提交。
6. **处理远端关系并推送。** 如出现远端新增提交或分叉，先检查差异并在授权范围内整合，保护本地未提交改动。不以强制推送、硬重置或清理未跟踪文件来“同步”。
7. **确认结果。** 核对远端实际提交身份；若涉及预览发布，再核对对应提交的构建及相关页面。网络失败或证据不足就记录实际停留阶段。
8. **归档本任务。** 将已完成的本任务记录迁入历史，登记实际提交号及可用的推送/构建证据，更新状态与索引；其他未发布任务和候选继续留在当前清单。

历史上使用过的故障处理办法不自动成为默认流程。改用其他传输方式时也要保持相同仓库、提交范围、提交身份及非破坏性边界。

## 4. 排除规则

`.gitignore` 负责通用不跟踪文件；当前未发布清单负责业务上的暂不发布决定，两者不能互相替代。Git 官方说明：已跟踪文件不受 `.gitignore` 影响，因此仅添加忽略模式不能保证它不进入后续提交。[Git 官方文档](https://git-scm.com/docs/gitignore)

未发布不等于永远忽略。正式任务尚未发布的代码不能全部加入 `.gitignore`；候选素材也不因整理规则而删除。候选清单继续保留，目录迁移后同步其路径；`.gitignore` 排除 outputs、工具二进制、个人 Obsidian 状态和机器 MCP 配置。

项目规则、知识、视觉记录和代码按本任务需要一起维护；不要承诺自动同步所有聊天记忆。本机凭据、机器绝对路径配置、临时状态不能混入提交。AOCI 正式文本索引已完成治理对齐，覆盖与技术跳过边界见实施状态；专用资产边界采用 `.aoci/.gitignore` 的官方白名单，接入状态见 [[docs/standardization-status|实施状态]]。

## 5. 结果用语

| 状态 | 必需证据 |
| --- | --- |
| 本地完成 / 待同步 | 修改与相称验证完成；尚无本次远端同步证明 |
| 已提交、未推送 | 本地 commit 存在；未确认远端包含它 |
| 已同步 GitHub | 已核对目标远端分支包含相应提交 |
| 已发布预览 | 已核对对应提交的预览构建成功与相关页面结果 |

GitHub 文档将 push 定义为把本地提交送到远端，因此“有提交号”和“已同步 GitHub”须分开记录。[GitHub 推送说明](https://docs.github.com/en/get-started/using-git/pushing-commits-to-a-remote-repository)

历史标题中的“已发布”保留原始记录，以条目内实际证据解释；新记录使用上述状态，不倒改历史结果。
