## 盘点结果

- 改前：1 份根 `AGENTS.md`（8,025 字节），没有仓库级 `SKILL.md`、`.agents/skills`、`.codex` 配置或 `.github` 工作流；没有 package.json/测试依赖锁文件。
- 改后：根规则 4,987 字节，缩减约 38%；新增频道维护、弹窗维护 2 个仓库级 Skill。细节按需读 `docs/maintenance-workflow.md`，导航几何继续以原模块笔记为准。
- `AI Agent/` 是网页助手及本地 Mock，不是 Codex 配置。`docs/agent-notes.md` 只有一句说明，也不是自动加载的 Skill。
- 当前会话工作目录为 Git 根的父目录 `GAIP项目集`；Git 根实际是其下的 `样式优化html`。官方的向上/沿路径发现规则不等于递归发现所有子仓库，因此不能保证从父目录启动时自动加载子仓库 Skill。建议将保存的 Codex 项目指向实际 Git 根。此次未更改应用项目设置。
- 个人 `~/.codex/AGENTS.md` 当前为空。本次阅读了相关个人 `frontend-design`、`obsidian-markdown`、`obsidian-cli` 以检查适配风险；未审计所有个人/插件技能全文，也未修改其源文件或全局启用状态。仓库外技能不随仓库提交。

## Skill 使用与验证场景

项目从实际 Git 根打开后，可使用 `$gaip-channel-maintenance` 或 `$gaip-modal-maintenance`；也保留按 description 自动匹配。当前运行中任务是否即时刷新技能列表取决于宿主；未出现时新开正确项目的任务，并可明确提供 Skill 路径。仅写“已创建”不等于已验证宿主自动发现。

| 真实请求 | 预期路由与验收 |
| --- | --- |
| “方案中心改完，其他入口还是旧页面” | 频道 Skill；找注册表和 features 单一源码，核对跨入口；不把 HTML 重写成完整页面 |
| “刷新总回导入工作台” | 频道 Skill；保留当前 Hash、检查虚拟入口默认值；不使用整页跳转修复 |
| “配置中心父菜单只展开” | 频道 Skill；父项纯开合、其他频道不卸载、键盘状态正确 |
| “关闭弹窗后导航点不了，修复” | 弹窗 Skill；查显隐/遮挡/事件，验证关闭后点击与再次打开 |
| “新增公告删除确认并加组件预览” | 弹窗 Skill；真实源登记、共享确认组件、生成索引、预览同源 |
| “只把百宝箱换成附件，别改样式” | 两者均不触发；直接替换所属资源，核对附件/引用/缓存 |
| “为什么导航不能点击？先不要改” | 诊断范围；可读相关 Skill，但不自动写文件或发布 |
| “更新一条知识库记录” | 文本操作即可；不要求打开 Obsidian、不跑全部业务测试 |

这些场景用于人工审查触发范围和今后的任务回放，未声称做过独立模型的成功率评测。官方 Skill 校验器只检验基础结构，不能证明模型一定正确选择技能。

## 非 Agent / Skill：建议的实施顺序

| 优先级 | 仓库证据 | 建议及可验收结果 | 官方原则/适用边界 |
| --- | --- | --- | --- |
| P0 | 5 个 DOM 测试 `require('jsdom')`，无依赖清单；本次之前依赖消失导致测试无法启动 | 增加仅开发用 package.json、精确依赖和锁文件、统一测试命令；全新 checkout 能一次安装并执行。网页继续可双击打开 | Local environments 的环境可复现原则；选何种包管理器是工程决策 |
| P0 | 弹窗关闭拦截点击；现有测试大量依赖源码正则或 DOM 模拟 | 补真实浏览器回归：导航 → 打开弹窗 → 关闭 → 点击底层 → 再开，记录命中元素/控制台/主文档是否重载；至少两条入口和刷新路径 | Prompting Codex 的复现与验证原则；具体浏览器框架另行选择，必须遵守当前工具权限 |
| P1 | 共享 CSS/JS 版本散落在 16 个本地根入口及组件预览，之前每次手工批量替换 | 建立共享资源版本清单和入口生成/校验命令；保留频道专有差异、加载顺序与无 Hash 默认值；`--check` 能发现漏同步 | 将重复步骤做成确定性工具的项目应用，不是官方要求使用某种构建框架 |
| P1 | 仓库内无 `.github` 检查流程；发布排除项靠文字说明 | 先提供本地发布文件清单及检查，再接 CI：导航/登记/相关测试失败阻止发布；测试视频和试验素材不进入产物 | 官方代码审查与环境指导；启用远程检查/部署属于后续单独实施 |
| P1 | 多任务共用 checkout；本次审计尚在校验时，另一发布任务已经提交其中间文档 | 新的大功能用独立 worktree；集成前核对 shared/config、根入口及当前变更记录；先完成验证再交接发布，主预览在集成后验收 | Worktrees 官方隔离机制；Obsidian 双链不能替代 Git 集成 |
| P2 | `channel-features.js` 插入全部资源后立即标 ready，脚本仅标频道 error，没有 stylesheet error/完成状态 | 将“已登记/加载中/完成/失败”区分，保留依赖顺序；失败可定位具体资源。评估惰性加载需先保证跨入口契约 | 可靠验收与可诊断性的工程推论；本次不直接修改运行时 |
| P2 | `频道资源加载.md` 中 registry 版本写 20260904-67，而根入口已是 20260904-73 | 文档只保存职责与定位；易变版本从源码清单生成检查，增加链接和状态一致性检查，减少手工重复 | AGENTS/Skill 渐进加载与单一事实来源的项目应用 |
| P2 | `docs/README.md` 仍说仅调整离线路径，而 features 已有大量本地改版；`docs/agent-notes.md` 仅占位 | 更新开发说明，区分原站基线、本地扩展和 Mock；确认无引用后再归档占位文档 | Prompting 的有效上下文原则，属于维护建议 |

优先做“稳定测试环境 + 真实点击回归”。它们能让优化是否成功有可重复的证据。Skill 能减少误操作，但不能代替资源加载机制、CSS 层叠规则和浏览器命中测试。

无需为本次目标引入真实 OpenAI API、密钥、Responses/ChatKit、生产登录或后端；网页助手目前是本地 Mock。模型 API 的缓存、计费、temperature 等迁移指导没有直接适用的生产调用点，不能机械套用。也不建议仅因“更现代”就把 Umi 静态站改成另一套框架。
