## 审计范围

本次审计覆盖主导航下 9 个频道首页：

1. 工作台总览
2. 客户中心360
3. 保单列表
4. 方案中心
5. 产品中心
6. 活动中心
7. 薄荷入职引导
8. 线索中心
9. 学习中心

`qa/channel-home-audit-20260731/` 中的截图只作为视觉基线，不作为结构规范的唯一依据。

## 已确认的问题

### 1. 频道定义重复

频道名称、路由、入口文件和图标映射分别存在于：

- 12 个 HTML 入口文件
- `channel-entry-navigation.js`
- `learning-nav.js`
- `channel-regions.js`

新增或改名频道时需要同时修改多处，容易出现导航名称、页面名称和入口文件不一致。
例如当前“薄荷入职引导”和“薄荷入职指引”同时存在。

### 2. 页面布局规则缺少统一来源

当前页面间已经自然形成部分共同值：

- 页级常用边距：`24px`
- 常用区块间距：`24px`
- 常用控件高度：`36 / 40 / 48px`
- 高频圆角：`4 / 6 / 8px`

但这些值直接散落在各频道构建产物和扩展 CSS 中，没有公共设计变量，也没有明确使用边界。

### 3. 滚动模型不一致

当前同时存在三种方式：

- 页面随文档纵向滚动
- `height: calc(100vh - 56px)` 的内部滚动
- 多个嵌套容器分别滚动

滚动方式应由页面类型决定，而不是由单个模块临时决定。每个频道首页原则上只能有一个
主要纵向滚动容器。

### 4. 频道区域标识覆盖不完整

`channel-regions.js` 已经建立稳定结构名称，但不同页面标记深度不一致：

- 客户中心只有内容侧栏和内容主体，没有共同的页面内容容器。
- 产品中心以频道导航作为页面顶部，没有频道页头。
- 工作台、保单列表和方案中心将标题、说明和操作直接放在主视觉区中。

这些不一定是视觉错误，但规范需要明确哪些区域是必需、可选或互斥的。

### 5. 页面资源全部全局加载

每个 HTML 入口都会加载工作台、线索中心和学习中心的全部扩展 CSS/JS。
离线预览可以继续这样处理，但交付前端时应按频道或路由拆分，避免页面功能互相影响。

### 6. 构建产物不适合作为规范层

`web/` 下页面 CSS 为带哈希的压缩构建产物。规范层不应直接大规模改写这些文件，
应通过 `shared/` 中的公共配置、设计变量、结构标识和有限覆盖样式落地。

## 审计结论

整体不需要推翻重做。现有项目已经有稳定的顶栏、侧栏、品牌色、24px 页面节奏和四类
频道骨架。第一阶段应优先完成：

1. 建立唯一频道注册表。
2. 建立频道首页公共设计变量。
3. 明确四类页面的滚动、间距和区域组合。
4. 用稳定区域名称应用规范，避免依赖 CSS Modules 哈希类名。
5. 分类型逐页调整，不把所有频道强行做成同一布局。
