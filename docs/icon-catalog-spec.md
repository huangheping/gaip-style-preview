# 全局图标盘点与集中维护

入口：[全局组件 → 图标](../components/index.html?component=icons)，与表单弹窗框架等组件并列。所有运行图标维护源统一在 `shared/assets/icons/`；当前不同风格版本保留，供逐项比较和合并。

## 维护源与运行方式

- `registry.json` 登记 SVG、位图、内联 SVG、CSS 绘制规则的来源与消费者；目录按操作、导航、状态、表单、业务、品牌和第三方分类。
- 69 个 Ant Design 静态图标已导出本地 SVG，生成树数据供实际 React/Ant 组件使用。保留组件、事件及调用方属性；未登记的自定义 icon 不接管。第三方原站基线和历史归档只读。
- 模板中的静态 SVG 与 CSS 规则由中央文件同步到原位置的有界区段，保持模板绑定、CSS 顺序和原节点。15 个有限动态版本改为完整 SVG，构建为同步缓存；关闭遮罩仍保留同源 data 副本。
- 修改维护源后运行 `npm run build:icons`，生成本地图标缓存、目录、HTML 缓存与入口。`check:icons` 检查源与缓存一致；`npm run test:icons` 核对第三方绘图数据、实际组件接入、动态 URL 和目录行为。不要手改生成副本。

## 预览

列表每个图形只展示一个20px等比样例，卡片保留名称、固定编号、版本比较和默认折叠的来源详情；尺寸说明集中在列表说明中，不逐卡重复。原声明与页面尺寸待核验状态保留在来源详情中，20px预览不证明业务页面已迁移或实测，也不把业务尺寸统一改为20px。SVG 用同源内联克隆保留 currentColor，克隆单独处理 ID 及引用；带自有样式的独立 SVG、位图直接引用本地图片。原路径、描边和固定色保留，currentColor 在中性预览宿主中比较。

重复矢量在目录按画布、绘图节点和属性归并展示，保留来源与别名；仅归并展示不删除业务文件。用户按编号确定合并后，实际消费者改为同一中央 SVG，退出多余维护源。分类、搜索、同用途版本与尺寸筛选可组合，标准库保持待定稿。

## 合并评审编号

同用途不同版本的卡片展示固定编号，例如 `01-2`：`01` 是用途组，`2` 是该组版本。普通排列与「同用途不同版本」排列使用同一编号，搜索支持编号。用户单独输入 `02-2` 或“合并02-2”，均表示保留该版本并把同组其他版本合并到它；明确限定某两个版本时只合并指定范围。相互冲突的保留要求先澄清。

合并关系由 `shared/assets/icons/registry.json` 的 `reviewMerges` 维护：保留原编号、原 SVG 与全部来源，旧编号成为搜索别名，卡片展示已合并编号。Ant 模块名称、主题及组件调用属性保留，绘图读取选定 SVG；模板只保留宿主尺寸、class、ARIA 等上下文属性。缺少 viewBox 的定尺寸原件在生成副本中补对应画布，原件不改。生成实例去掉无引用的绘图 ID，避免重复 ID。`mergedFrom` 是删除来源的追溯记录，不是运行依赖。

`components/icons/icon-review-sequences.json` 保存用途与图形 ID 的编号对应，是编号维护源。构建只追加新组/新版本，保留已移除图形的编号记录，不重用和重排旧号；后续合并不删除此登记。图形内容变更产生新的图形 ID 时按新增版本处理；已有图形用途改变时构建会拒绝，需显式核对原编号与用途。该组别沿用现有用途候选，不表示所有状态应直接合并。

CSS图形按名称合并由registry.json的cssGlyphMerges登记：保留卡片、退出卡片、中央CSS源和消费者。2026-10-02“收起下拉”并入“更多操作收起”，真实控件读取同一组CSS绘图；表格原声明、选择器关闭态和已有编号保留。旧名称可搜索，删除1份旧CSS源；证据见 outputs/icon-collapse-merge-20261002/acceptance.md。
